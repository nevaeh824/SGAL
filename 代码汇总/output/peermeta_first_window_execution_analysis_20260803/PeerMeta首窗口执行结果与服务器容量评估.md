# PeerMeta 首窗口执行结果与服务器容量评估

生成日期：2026-08-03  
评估对象：`peermeta预测模型_首窗口计时.py`

## 1. 结论摘要

当前 17 模型、3 年训练窗口的首窗口测试已经完整运行成功：850 次模型拟合全部成功，2018Q1 的 2,892 条测试记录在 10 轮 SG-AL 后全部完成预测。

本次运行总墙钟为 **56 小时 57 分**，其中 NCA 的 50 次拟合累计耗时 **53.85 小时**，相当于总墙钟的 **94.54%**。因此，进一步增加普通模型并发不能显著缩短总工期；真正需要优化的是 NCA 的调度和内存容量。

在保持 NCA 全样本、算法和参数不变的条件下：

- **最低推荐配置：96 GiB 物理内存，运行 2 条 NCA 通道。**
- **稳妥配置：128 GiB 物理内存。**它主要提供更大的峰值内存余量，理论速度几乎不会优于 96 GiB 双通道方案。
- 按本次逐模型日志回放，双通道可将总耗时从 56.96 小时降低到约 **34.67 小时**。
- 考虑服务器单核性能、内存带宽竞争和调度开销，现实规划区间为 **35–42 小时**。
- 如果目标服务器能让单次 NCA 获得 1.3–1.5 倍实测加速，总耗时可能进一步降低到约 **24–27 小时**，但必须通过服务器基准测试确认。

## 6. NCA 内存评估

### 6.1 计算方法

当前环境使用 scikit-learn 1.3.2。`NeighborhoodComponentsAnalysis._loss_grad_lbfgs` 在核心计算中需要一个布尔类掩码和四个 float64 的 `n × n` 矩阵。

核心矩阵内存下界近似为：

```text
核心内存 GiB = 33 × n² / 2³⁰
```

该数值只是核心矩阵下界，不包括：

- 距离计算和 softmax 的临时数组。
- 数组复制。
- 输入特征矩阵。
- Python 和 scikit-learn 对象。
- 父进程与子进程运行时。
- 普通模型进程。
- 操作系统和文件缓存。

本评估采用以下规划口径：

```text
规划内存 = 核心矩阵下界 × 1.25 + 8 GiB
```

### 6.2 第 10 轮任务规模

| NCA 任务 | 拟合行数 | 核心矩阵下界 |
|---|---:|---:|
| 第一层完整训练 | 32,079 | 31.63 GiB |
| 第一层 OOF fold 0 | 23,072 | 16.36 GiB |
| 第一层 OOF fold 1 | 22,207 | 15.16 GiB |
| 第一层 OOF fold 2 | 18,879 | 10.95 GiB |
| 第二层完整训练 | 32,079 | 31.63 GiB |

完整训练和最大 OOF 同时运行时：

```text
核心矩阵下界 = 31.63 + 16.36 = 47.99 GiB
规划需求       = 47.99 × 1.25 + 8 = 67.98 GiB
```

因此 64 GiB 服务器不适合让完整训练 NCA 与 OOF NCA 同时运行，96 GiB 是双通道方案的最低推荐容量。

四个第一层 NCA 同时运行时：

```text
核心矩阵下界 = 31.63 + 16.36 + 15.16 + 10.95 = 74.10 GiB
规划需求       = 74.10 × 1.25 + 8 = 100.62 GiB
```

因此四通道方案应配置至少 128 GiB。

## 7. 服务器配置与速度预估

### 7.1 日志关键路径回放

耗时估算不是简单地把 NCA 总时间除以进程数，而是按照真实依赖关系逐轮回放：

1. 第一层完整训练 NCA 与三个 OOF NCA 互相独立，可以并行。
2. 第二层 NCA 必须等待第一层所有元特征产生，不能提前启动。
3. 普通模型及框架开销合计占约 3.11 小时墙钟。

| 服务器方案 | 调度方式 | 内存下界峰值 | 日志回放总耗时 | 相对当前速度 |
|---|---|---:|---:|---:|
| 当前 31.65 GiB | NCA 完全串行 | 31.63 GiB | 56.96 小时 | 1.00 倍 |
| 64 GiB | full 独占；OOF 最多 2 路 | 31.63 GiB | 48.02 小时 | 1.19 倍 |
| 96 GiB | full 一路；三个 OOF 共用另一路 | 47.99 GiB | 34.67 小时 | 1.64 倍 |
| 128 GiB | 第一层四个 NCA 同时运行 | 74.10 GiB | 34.66 小时 | 1.64 倍 |

两通道与四通道几乎没有速度差异。原因是每轮第一层完整训练 NCA 的耗时大致等于或超过三个 OOF NCA 的累计耗时：一条通道运行完整训练，另一条通道顺序运行三个 OOF，已经基本压缩到依赖图关键路径。

### 7.2 推荐服务器规格

建议的最低可用配置：

```text
物理内存：96 GiB
物理核心：至少 16 个，建议 24–32 个
NCA 通道：2
普通模型全局进程池：4–6 个
NCA 内部线程：1
普通模型内部线程：1
存储：NVMe SSD
重点：高内存带宽，避免低频大容量内存配置
```

建议的稳妥配置：

```text
物理内存：128 GiB
物理核心：24–32 个
NCA 通道：2；四通道只用于基准验证
普通模型全局进程池：4–6 个
存储：NVMe SSD
```

128 GiB 的主要价值是容纳无法从矩阵公式直接观察到的临时峰值，以及允许少量普通模型与 NCA 重叠运行，并不是显著缩短理论关键路径。

### 7.3 现实耗时区间

| 方案 | 现实规划耗时 |
|---|---:|
| 当前代码保持单 NCA、仅增加内存 | 约 45–57 小时 |
| 64 GiB、分阶段并行 OOF | 约 45–50 小时 |
| 96 GiB、双 NCA 通道 | 约 35–42 小时 |
| 128 GiB、四通道 | 约 35–43 小时 |
| 96/128 GiB，且单次 NCA 实测加速 1.3–1.5 倍 | 约 24–27 小时 |

当前机器为 Intel Core Ultra 7 265F、20 个物理核心、32 GiB DDR5-5600。该处理器单核性能并不弱，所以服务器拥有更多核心并不代表单次 NCA 一定更快。服务器优势主要来自：

- 容纳两个 NCA 进程而不分页。
- 更高的总内存带宽。
- 更大的物理内存余量。
- 更稳定的长时间持续运行能力。

## 8. 达到预估速度所需的代码调整

当前代码设置为：

```python
pipeline.NCA_EXCLUSIVE_PROCESS = True
```

因此，单纯把脚本复制到 96 GiB 或 128 GiB 服务器不会自动获得双 NCA 并发，仍需要修改调度器。

推荐的每轮第一层调度为：

```text
NCA 通道 A：第一层完整训练 NCA
NCA 通道 B：OOF fold 0 -> OOF fold 1 -> OOF fold 2

等待第一层全部完成

第二层：完整训练 NCA，单独运行
```

普通 16 模型应进入唯一的全局进程池，避免为每个 OOF 折创建独立进程池。禁止以下并发相乘：

```text
OOF 折并发 × 模型并发 × 模型内部线程并发
```

在获得峰值内存遥测之前，不建议让两个完整训练 NCA 同时运行。

## 9. 上服务器前的基准测试建议

正式运行前，应单独构造第 10 轮规模的五次 NCA 基准：

1. 第一层完整训练：32,079 行、143 个特征。
2. OOF fold 0：23,072 行、143 个特征。
3. OOF fold 1：22,207 行、143 个特征。
4. OOF fold 2：18,879 行、143 个特征。
5. 第二层完整训练：32,079 行、17 个元特征。

至少记录：

- 每个进程的峰值 RSS。
- 系统可用物理内存最低值。
- page faults 和页面换入换出。
- 内存带宽利用率。
- CPU 利用率。
- 每次 NCA 的实际耗时。
- 两个 NCA 同时运行后的单任务减速比例。

如果 `full + 最大 OOF` 的实测总峰值超过约 80 GiB，应直接使用 128 GiB，而不使用 96 GiB。

## 10. 结果解释限制

1. 当前指标只来自一个 2018Q1 测试窗口，不能替代正式多季度外推验证。
2. 当前任务使用第 t 季度最后可用周的特征识别第 t 季度 FSFP，属于同季度识别，不是预测 t+1 季度标签。
3. 当前没有保存运行期逐进程峰值 RSS、page faults 和内存带宽，因此内存结论是容量规划估算，不是峰值实测。
4. 34.67 小时是基于当前日志的调度回放值，新服务器实际结果会受单核性能、NUMA 和内存带宽竞争影响。
5. 当前部分模型没有统一固定 `random_state`，单次运行尚未给出重复性区间。
6. 注册表中的 `Probit` 实际为 SAG Logistic；`Tree-ID3` 和 `Tree-C4.5` 当前都使用 entropy，并非严格的统计 Probit 和原生 C4.5 实现。
7. 如果后续运行正式 5 年、5 折、多季度版本，需要根据每个窗口的真实训练行数重新计算 NCA 内存，不能直接复用本报告的 96/128 GiB 结论。

## 11. 最终建议

当前 3 年首窗口的最佳性价比方案是：

```text
96 GiB RAM
24–32 个物理核心
高内存带宽
2 条 NCA 通道
一个全局普通模型进程池
所有模型内部线程固定为 1
```

预计总耗时为 **35–42 小时**。如果更重视稳定性而不是采购成本，选择 128 GiB；它可以降低未知临时内存峰值造成的中断风险，但在当前依赖关系下不会比 96 GiB 明显更快。

在正式多季度运行前，应优先完成：

1. 双 NCA 通道调度。
2. 第 10 轮规模的服务器内存与耗时基准。
3. 每模型实时日志。
4. OOF 折级检查点。
5. 配置指纹与断点恢复。
